Red-Eye-Engine — HTTP 통신 처리 올인원 C# 라이브러리

2023 · GitHub · C#/.NET Framework 3.5 (DLL)

HTTP 요청·응답 처리를 한 벌로 묶어 동적 링크 라이브러리(DLL)로 배포하는 C# 클래스 라이브러리. 프록시·타임아웃·임의 헤더·gzip/deflate 자동 해제·쿠키 조립을 감싼 전송 함수군을 중심에 두고, 그 위에 이미지 보정·네트워크 어댑터 제어·ADB 연동·설정 파일 입출력 같은 주변 기능을 같은 어셈블리에 모았다.

핵심인 Engine 클래스가 HttpSend·HttpSendBytes·HttpSendSecureCookie·HttpSendSocket 네 갈래 전송 경로를 제공하고, 여기에 URL 인코딩/디코딩·MD5 해시·쿠키 병합·한글 자소 분해·조립 같은 문자열 유틸리티가 붙는다. .NET Framework 3.5를 대상으로 하는 클래스 라이브러리(OutputType=Library, AssemblyName=RedEyeEngine)이며, 2023년 8월 8일 6개 커밋으로 공개된 뒤 그대로 남아 있다.

구조 · 설계

하나의 어셈블리(RedEyeEngine.dll, .NET Framework 3.5 대상 클래스 라이브러리) 안에 역할별 클래스를 병렬로 둔 평평한 구조다. 중심은 Engine 클래스로, HttpWebRequest를 감싼 네 갈래 전송 경로를 제공한다. ① HttpSend — 문자열 본문 전송, ② HttpSendBytes — 바이트 배열 본문 전송, ③ HttpSendSecureCookie — 응답 쿠키 컬렉션 반환, ④ HttpSendSocket — 소켓 수준 전송. 네 경로 모두 '호스트:포트' 문자열 하나로 프록시를 지정하고, 타임아웃을 지정하며, 헤더는 '이름: 값' 문자열 리스트로 넘기면 User-Agent·Content-Type·Referer·KeepAlive·gzip/deflate 자동 해제 같은 항목을 알아서 대응 속성에 매핑한다. 응답은 전문(ALL)과 본문(CONTENTS) 중 원하는 형태로 받는다. 여기에 쿠키 병합(CookieProcess·CookieAssemble), URL 인코딩·디코딩, MD5 해시, 서버 인증서 검증 콜백, 시스템 정보·현재 공인 IP 조회, 한글 자소 분해·조립과 한↔영 타이핑 변환 같은 문자열 유틸리티가 같은 클래스에 붙는다. 주변 모듈은 기능별로 나뉜다. CoreInternetProtocols는 NIC 장치 목록 조회와 프록시·MAC·IP/서브넷/게이트웨이/DNS 변경, 어댑터 활성·비활성을 담당하고, CoreImage는 Bitmap의 대비·밝기·감마·그레이스케일·반전·리사이즈·회전/플립·테두리 처리를, CoreADB는 adb 명령 실행과 안드로이드 기기 IP 변경·화면 상태 확인·제어를, CoreInternetExplorer는 IE COM 개체(SHDocVw·MSHTML) 자동화와 창 메시지 전송을, CoreFramework와 CoreSettings는 파일 읽기·쓰기, 타이머 대기, INI 형식 설정 저장·로드를 맡는다.

설계 목표

여러 도구를 만들 때마다 매번 다시 쓰게 되는 HTTP 호출 코드를 한 번만 제대로 짜 두자는 것이 목적이었다. .NET의 HttpWebRequest는 프록시·타임아웃·헤더·압축·쿠키를 각각 다른 속성과 타입으로 다루기 때문에 요청 하나를 보내려면 매번 같은 준비 코드를 반복해야 한다. 그래서 그 준비 과정을 문자열 인자 몇 개로 접어 넣고, 결과를 문자열로 돌려받는 호출 하나로 줄였다. DLL로 배포한 이유도 같다. 호출 규약을 어셈블리 하나에 고정해 두면 새 프로젝트에서는 참조만 추가하면 되고, 여러 도구가 같은 통신 코드를 공유하게 된다. HTTP만으로 끝나지 않는 작업 — 응답으로 받은 이미지를 손보거나, 요청을 보낼 네트워크 어댑터 설정을 바꾸거나, 연결한 안드로이드 기기를 조작해야 하는 상황 — 을 위해 주변 모듈을 같은 어셈블리에 함께 넣어, 참조 하나로 필요한 도구가 전부 따라오게 했다. 2023년 8월 공개 이후 새 커밋이 없는 상태로, 사용 목적을 다한 지난 세대의 작업 기반을 기록해 두는 성격의 저장소다.
